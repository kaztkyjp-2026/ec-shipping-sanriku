# EC出荷オペレーションツール（ec-shipping-sanriku）

Amazon FBM（自己発送・2店舗）と楽天市場の出荷業務を1つの画面で処理するブラウザツールです。

**🔗 ツール：https://kaztkyjp-2026.github.io/ec-shipping-sanriku/**

## 対応モール

- **Amazon**（FBM・2店舗）
- **楽天市場**

## 主な機能

| タブ | 機能 |
|---|---|
| 依頼主設定 | Amazon 店舗（複数）と楽天市場（B2依頼主・1店舗）の依頼主情報を登録。ブラウザに保存し、Google ログイン中は Drive（`EC出荷記録/00_ツール設定`）に控えを取る。ブラウザの設定が空のときは Drive の控えから戻せる |
| STEP 1 | Amazon 未出荷注文レポート（タブ区切り）＋楽天市場 通常購入データCSV（全カラム）＋発送完了報告用DLデータ（6列）→ ヤマトB2クラウド取込CSV（1ファイル） |
| STEP 1 | 発送方法を注文ごとに選択：Amazon・楽天とも全注文を「発送方法の確認・変更」の一覧に出し、5択（ネコポス／宅急便コンパクト／クリックポスト／宅急便／発行しない。Amazon の宅急便はセラーセントラルで発行、楽天の宅急便は B2 で発行）。楽天で配送方法が不明の注文は初期値「不明（B2から除外）」。一覧は既定で閉じ、Amazon の別発行・楽天の不明があれば開く。注文ごとに個口数（1〜10）も選べ、N個口の注文は B2取込CSV・クリックポスト用CSV に同じ行を N 行出す |
| STEP 1 | クリックポストを選んだ注文 → クリックポスト用CSV（GoQ の拡張で取り込む。40行ごとに分割し、同じ注文の行はファイルをまたがない） |
| STEP 1 | 出力前に Drive の記録（直近7日の B2用CSV・発行済データ・クリックポストの記録）と照合し、発行済み・出力済みの注文を除外（照合A）。照合できないときは「照合なしで出力」 |
| STEP 1 | ピッキングリスト（商品別集計・A4たて）＋梱包・発送明細（A4よこ）を1文書で印刷。帳票には常に Amazon・楽天市場の両方を出す（注文0件は「注文：0件」、読み込んでいないモールは「未読込」。読み込んだモールが0件でも印刷できる）。商品別集計の列は「出荷個口数（注文数）」（個口数の合計と注文数。ピッキング合計と出荷個口数が違う行を黒地で示す）。梱包・発送明細は行番号を「（001）」と括弧で括り、全注文に配送方法の表記（ネコポス＝黒枠／宅急便コンパクト＝黄緑／宅急便＝深緑／クリックポスト・発行しない・別発行＝赤）と、2個口以上なら「N個口」の札。ピッキングリストの末尾に配送方法別内訳（Amazon／楽天市場／合計＝注文数／個口数。未読込のモールは「—」。ヤマトへは種類ごとに個口数で申告。個口数の列は太線で囲む） |
| STEP 1（楽天市場） | ステータス 300（発送待ち）以外、MCF注文（ひとことメモ CONSUMER-）、発送完了報告済み（DLデータにお荷物伝票番号あり）、お届け日が本日+4日以降の予定分を除外し、警告を表示 |
| STEP 2 | B2クラウド発行済みデータCSV（複数可）→ Amazon 出荷通知TXT（ファイルごと・店舗ごと）＋楽天市場 発送完了報告CSV。お客様管理番号の形式で振り分け |
| STEP 2 | GoQ のクリックポストのレポートを同じ欄で読み、伝票番号を照合して出荷通知に合流（Amazon：Japan Post／楽天：配送会社 1003）。手入力も可。複数個口は同じ注文の行が両側で同じ数なら照合を通す。伝票番号は注文単位で扱い、一部の行だけ入れた複数個口は Amazon は入れた先頭1本で通知、楽天は手動報告の警告に回す |
| STEP 2 | 出荷通知ファイルを作る前に発行済データを Drive（03_発行済データ）へ保存。保存できなければ作らない |
| STEP 2 | 伝票が2枚以上ある注文（個口数を2以上にした注文、またはB2で同じ注文の送り状を2枚以上発行）を警告。複数個口は Amazon は先頭1本だけ通知、楽天は手動報告（クリックポストも同じ） |

- 楽天市場の STEP 2 は RMS のテンプレートCSV不要。送付先ID は STEP 1 で読み込んだ通常購入データから取る（同じ画面で STEP 1 の楽天①を読み込んでいること）
- 「Amazon／楽天市場」スイッチは STEP 1 にだけある（表示の切り替えのみ。出力は1ファイルに統合）
- 出力ファイルはブラウザのダウンロードとして直接保存（フォルダ選択なし）。ピッキングリストの PDF はブラウザの印刷ダイアログの「PDFとして保存」で作る
- Shift-JIS の入出力に対応（クオート内改行を含む RMS CSV にも対応）
- 商品サムネイル（sku-images.json）付きピッキングリスト（Amazon／楽天市場とも）
- G番号は接頭辞でモールを区別（Amazon: A-001 ／ 楽天市場: R-001。B2記事欄も同形式）。複数商品の注文は中身ごとに「複-01」等の識別子で1行にまとめる

## データの保存先

処理はブラウザ内で行います。Google にログイン（`drive.file` 権限）している間は、入力ファイル・B2用CSV・発行済データ・クリックポスト関連ファイル・店舗設定の控えを**利用者自身の Google ドライブ**のフォルダ「EC出荷記録」に保存し、照合Aで読み出します。作成者のサーバーへは送信しません。STEP 2 の出力（出荷通知TXT・発送完了報告CSV）は Drive に保存しません。未ログインの間は保存しません。ログイン状態はページを開いている間だけ保持します。

## 動作環境

PC 版の Chrome / Edge。サーバー不要。Drive 保存・照合には Google アカウントでのログインが必要。
